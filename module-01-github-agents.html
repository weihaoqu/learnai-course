GitHub + Agents

Today we connect two ideas: GitHub is where software work becomes visible, and agents are AI systems that can help move work through a controlled loop.

No blind trust

Part 1 question

Why does GitHub matter for AI work?

If an AI assistant changes code, you need a place where the task, files, proposed changes, review, and history are visible. GitHub is that shared workspace.

task -> repo -> change -> diff -> review -> commit
Repository

A repo is a project with memory.

A repository holds files plus the history of how those files changed. That history matters because AI work should be inspectable and reversible.

Files

The current project state: HTML, CSS, JavaScript, docs, images, tests.

History

The record of who changed what, when, and why.

Commit

A commit is a named checkpoint.

Good commits make work understandable later. A useful commit answers: what changed, why, and where should a reviewer look?

commit 8c14... Add quiz feedback to Module 0 slides - adds interactive quiz choices - preserves keyboard navigation - verifies mobile layout
Ask students which line is most useful to a future teammate. Usually it is the concise title plus the why.
Branch + PR

A branch lets you try work before merging it.

Branch

A separate workspace for a change. It protects the main version while you experiment.

Pull request

A review request that shows the diff, discussion, checks, and decision before merge.

main
->
branch
->
PR
->
merge
Issue

An issue is a task with context.

Agents work better when the task is written down. A good issue includes the problem, the desired outcome, constraints, files to inspect, and how to know the work is done.

problem + constraints + done condition = usable task
Quick check

Which object is the review request?

A pull request packages the change for review: diff, discussion, checks, and merge decision.
Challenge 1 - 15 minutes

Map a repo before changing it.

Given a small project, identify the likely files for each responsibility.

Content

Where is the text students see?

Style

Where are layout and colors defined?

Behavior

Where do clicks, quizzes, or navigation run?

Deliverable: a three-line repo map.

Challenge 2 - 12 minutes

Read a diff like a reviewer.

In a diff, removed lines usually start with minus and added lines with plus. Your job is to explain the behavioral change, not just count lines.

- button.textContent = "Submit"; + button.textContent = "Check answer"; + feedback.hidden = false;

Deliverable: one sentence describing what the user now experiences.

Quick check

What changed in the diff?

Reviewers translate code changes into user-visible behavior and risk.
Part 2 question

What makes an AI assistant an agent?

An agent uses an LLM inside a loop. It has a goal, context, tools, observations, and stopping rules.

LLM + goal + context + tools + loop + guardrails
Three levels

Answer, tool call, or agent loop?

LLM answer

Responds in text from context.

Tool call

Requests an external action such as reading a file or running a test.

Agent loop

Plans, acts, observes, and revises across multiple steps.

Loop

The loop is where usefulness and risk both grow.

task
->
plan
->
tool
->
observe
->
revise

The loop should stop when the task is done, blocked, too risky, or waiting on human approval.

Human control

The agent should not approve itself for powerful actions.

Changing a file in a local exercise is low risk. Publishing, deleting, spending, emailing, or touching personal data is different. Those actions need human approval.

Fast path

Draft text, summarize, suggest, explain, make reversible local changes.

Approval path

Send, publish, delete, merge, spend, expose private information, or affect other people.

Quick check

Which one is an agent loop?

An agent loop has multiple steps with observations and revision, usually involving tools.
Challenge 3 - 10 minutes

Fast path or approval path?

Sort each action into fast path or approval path, then explain one borderline case.

  • Summarize a README.
  • Commit code to a branch.
  • Merge to the main branch.
  • Email a project update to outside partners.
  • Generate three alternate button labels.

Deliverable: one rule your group would give an agent.

Part 3 question

How do we work with an agent without losing control?

Use a small loop: write the task, ask for a plan, inspect the plan, allow a tiny change, review the diff, then decide.

issue -> plan -> tiny change -> diff -> review -> commit
Task writing

A good agent task has boundaries.

Goal: Change the quiz button label from "Submit" to "Check answer". Files to inspect: module-00-llm-basics.html Constraints: Do not change slide navigation. Done when: The button text changes and quiz feedback still works.

Boundaries make agent work smaller, reviewable, and safer.

Challenge 4 - 12 minutes

Ask for a plan before code.

Write a prompt that asks an AI assistant for a plan, not an immediate edit. The plan must mention files, risks, and verification.

"Before changing files, inspect the relevant code and give me a short plan with verification steps."

Deliverable: one plan-first prompt.

Challenge 5 - 18 minutes

Review the agent's proposed change.

You receive a small diff. Decide whether to accept, ask for revision, or reject. Your answer must include evidence.

Check behavior

Does the change match the task?

Check blast radius

Did it touch unrelated files or behavior?

Check verification

How do we know it still works?

Check wording

Would another student understand it?

Quick check

What should come before accepting an agent's code?

Agent work becomes useful when humans review the evidence and decide.
Challenge 6 - 25 minutes

Mini lab: one tiny safe change

In pairs, complete a controlled workflow. If accounts or live tools are not available, use the instructor's projected repo and printed diff.

1. Task

Write a small issue with a done condition.

2. Plan

Ask the assistant for a plan first.

3. Review

Inspect the proposed diff before accepting.

This can be live with GitHub or fully simulated. The learning target is the control loop, not account setup.
Exit check

Choose the best commit message.

A good commit message is specific enough for a future reviewer to understand the change.
