Week 9: Interactivity and Simple Intelligence
Slide 1
60-minute build studio

Add behavior to your Week 8 app.

Week 8 produced a one-screen app brief. Week 9 turns that brief into a working interaction: inputs, a button, validation, simple rules, an output card, and test cases.

In class

Use Study Break Picker as the shared demo, then adapt the pattern to each student's app.

Boundary

Frontend only. No backend, database, login, public posting, API keys, or private student data.

Artifact

Week 9 Interactive Feature Brief: feature, rules, validation, output, test cases, and agent prompt.

Pacing: 4 minutes. Say explicitly that edit/build actions are allowed only after human approval and verification. Week 9 is not an API-key lesson.
4-10 min

Your Week 8 brief already contains the Week 9 feature map.

Do not restart the project. Translate the design brief into code responsibilities.

User

Who uses the app?

Inputs

What facts does the app need?

Event

What button or action starts the feature?

Rules

How does the app choose an output?

Output

What result can the user judge?

Privacy guard

Use fictional, low-risk, or generic inputs. Do not ask students to enter health details, family information, exact locations, grades, finances, account credentials, or private schedules.

10-24 min

Demo: Study Break Picker.

A simple app can feel intelligent without a model API. It reads inputs, checks for missing information, applies rules, and renders a useful output.

Try the demo. Leave one field blank first so students see validation before generation.
Ask students to identify the HTML, CSS, JavaScript event, validation rule, state, and output area in the demo.
24-32 min

The interaction pipeline has five parts.

Students do not need to memorize syntax first. They need a mental model they can use when prompting and reviewing an agent.

Connect this to agent review: when a feature fails, students should say which part of the pipeline failed instead of saying "the app is broken."
32-40 min

Simple intelligence means bounded rules, not hidden magic.

For Week 9, intelligence can be a decision table, scoring rule, category match, template, checklist, or random choice inside safe boundaries.

Input patternRuleOutput behavior
5 minutes + low energyKeep it short and low effort.Breathing reset, desk stretch, or one-song break.
20 minutes + high energyAllow movement, but keep return easy.Walk, quick workout, or room reset with a timer.
Blank or vague inputAsk for the missing field.Helpful validation message, not a fake recommendation.

Bad rule

"If the student seems stressed, tell them what they should do." This guesses private state and overreaches.

Better rule

"If energy is low, suggest a low-effort break and remind the user to choose what fits them." This is bounded and reviewable.

40-50 min

Ask your agent for one adaptive feature.

Students can use Claude Code or Codex. The important move is to give the agent a small feature contract and then approve or reject its edits after review.

50-56 min

Write tests before you trust the feature.

A feature is not finished when the agent says it is finished. It is finished when the student can run examples and explain the result.

Require at least one failed or edge case. This teaches students to verify behavior instead of admiring the first working demo.
56-60 min

Human review is still the control system.

An agent may edit code, but students must inspect, test, and approve the result. This connects Week 9 back to the Week 2 agent loop.

Observe

Run the app. Write what happened, not what you hoped happened.

Diagnose

Name the pipeline part: input, event, validation, state, rule, or output.

Approve

Accept edits only after the test cases pass and the boundary is still respected.
