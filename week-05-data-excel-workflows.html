Week 5: Data, Excel, and Administrative Workflows
Slide 1
60-minute data lab

AI can accelerate spreadsheet work. The spreadsheet remains the evidence.

Today students use agents for cleaning, formulas, charts, and short admin summaries. The target is not a perfect dashboard. The target is a workbook whose data, changes, and claims can be checked.

In class

Diagnose a messy synthetic table, ask for formula help, critique a chart, and build an evidence packet.

Tools

Copilot in Excel is the main path when available. Claude file analysis is optional when enabled. A sample AI response keeps the lab tool-neutral.

Rule

Keep a raw copy, do not fabricate missing data, verify two rows by hand, and disclose AI assistance.

Pacing: 5 minutes. Ask students what an agent can do quickly and what would still be dangerous to trust.
Source boundaries

Tool docs describe capabilities. Class policy controls the data.

Use today

  • Microsoft describes Copilot in Excel as able to edit worksheets, generate formulas, create charts/PivotTables, and surface insights.
  • Microsoft recommends specific prompts that name columns or ranges, then refining with follow-ups.
  • Claude can support CSV/XLSX analysis and spreadsheet generation when the needed file features are enabled.

Guardrails

  • Availability depends on account, subscription, file format, tenant settings, and workbook structure.
  • Use synthetic or approved data only. Do not upload private student, medical, financial, customer, workplace, password, or API-key data.
  • Review, edit, and verify AI-generated content before using it.

Lab 2: formula help still needs row-level verification.

AI can propose formulas. Students must explain them and check at least two rows manually.

Formula 1 of 5

Formula verification habit

  • Read the formula in plain English.
  • Check two rows by hand.
  • Check missing values and zero denominators.
  • Confirm units: dollars, people, dates, percentages.
  • Do not hide errors without explaining them.

Choose the valid critiques

Valid critiques focus on data, units, grouping, duplicates, and whether the chart supports the claim.
Chart revision checkpoint

Reflection turns critique into a better version.

A reflection loop is useful when the first output can be checked against new evidence: raw rows, formulas, labels, units, or reviewer feedback.

Reflection loop for charts First output -> critique with criteria -> revision request -> revised output Critique criteria: - Does the chart match the raw data? - Are units, labels, and grouping clear? - Does the visual support the claim? - What evidence changed your mind? Revision request: Use the critique above. Propose a clearer chart and explain what changed.
Use this as an original LearnAI bridge from chart critique to reflection. Do not use external examples, copied prompts, model names, benchmark claims, diagrams, or lab setup/code.
Reflection check

Measure the revision, not the vibe.

Reflection adds a step, so keep it only when the revised output is easier to verify or clearly more accurate.

Reflection eval Same source file, same task, two outputs: A = first chart B = revised chart after critique Score each 0/1: [ ] raw rows match [ ] formula spot check passes [ ] labels and units are clear [ ] chart type supports the claim [ ] disclosure is complete Keep reflection if B improves enough to justify the extra time.
Use this as a classroom-safe eval pattern. Students are not proving a universal AI claim; they are testing whether one extra review step helped on their own spreadsheet task.
Fresh evidence

Reflection works better with check results.

A critique is stronger when it receives facts from outside the draft, not just the draft again.

Fresh evidence for reflection Row-count check -> missing or extra rows Formula check -> wrong total or copied formula Chart label check -> missing units or unclear grouping Source check -> citation gap Privacy check -> disclosure or upload risk Length check -> memo too long Revision request: Use these check results. Fix only evidence-backed issues and explain what changed.
Connect this to tools students can actually use: spreadsheet filters, row counts, hand formula checks, source notes, privacy rules, and assignment length limits.
Formative check

Reflection quick check.

Answer each question before opening the card. Keep the examples tied to the same spreadsheet evidence packet.

1. What does reflection do after a first chart draft?

It checks the draft against criteria, uses evidence to critique weak parts, and asks for a revised version.

2. Why bring in formula checks or row counts?

They add fresh evidence that the draft cannot discover by rereading itself, such as a wrong total or missing row.

3. How should chart quality be scored?

Use clear yes/no criteria, then compare the first and revised outputs against the same scorecard.

4. When should reflection be removed?

Remove it when the scorecard does not improve enough to justify the extra time and extra review step.

This is an original LearnAI formative check. Do not reproduce external quiz wording, answer choices, or non-spreadsheet examples.

Homework rubric

What counts for the Week 5 homework?

Prompt quality

Goal, table/range, columns, output, constraints, and verification request are clear.

Formula verification

Two formulas are explained and two rows are checked by hand.

Chart critique

The chart or PivotTable is checked for units, labels, grouping, and supported claims.

Privacy decision

The data is synthetic, approved, or public with source. Sensitive data is not uploaded.

Evidence packet

Raw copy, prompt log, before/after evidence, reflection scorecard, changes, checks, and disclosure are included.

Rejected suggestion

One AI suggestion is rejected with a reason tied to data, formula, chart, privacy, or claim quality.

Homework

Due before Week 6.
