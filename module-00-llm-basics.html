Concept 1

What is an LLM?

A large language model is a computer model trained on large amounts of text and code so it can use context to predict useful next pieces of text.
Large

It has many learned parameters and was trained on massive examples.

Language

It works with text-like symbols: words, word pieces, punctuation, code, and numbers.

Model

It is not a person or database. It is a learned pattern system.

Useful output

It can explain, draft, translate, summarize, code, and plan, but still needs checking.

This slide should be read plainly. Students need the definition before the analogy.
Concept map

The basic LLM loop

The model reads the current context, estimates likely next tokens, chooses one, adds it to the answer, and repeats.

context
->
model
->
next-token choices
->
one token added
->
repeat

That repeated loop can produce a sentence, an explanation, code, or a plan.

Concept 2

What is a token?

A token is a chunk of text the model can process.

It may be a whole word, part of a word, punctuation, a space pattern, a number, or a code fragment.

unbelievable -> un believ able
user_id -> user _ id

This is why exact spelling, counting letters, and formatting can be surprisingly tricky.

Interactive check - 4 minutes

Click to reveal possible token chunks.

Real tokenizers use exact vocabularies, so the split can vary by model. The point here is the mental model: the model sees chunks, not full human meaning all at once.

One possible split: un / believ / able. A long word may become several familiar pieces.
One possible split: user / _ / id. Code and punctuation can be separate chunks.
Why counting can fail: the model may reason from chunks like straw / berry instead of directly counting every letter.

Pair prompt: how does chunking explain why an LLM can write fluent text but still stumble on exact spelling or counting?

Concept 3

What is context?

Context is the information the model can see right now.

It includes your prompt, recent conversation, pasted files, tool results, and system instructions. If something is outside the context, the model cannot directly use it.

Inside the context window

Your question: "Explain this bug."
The error message you pasted.
The relevant function.
A file you did not provide.
Concept 4

What is next-token prediction?

At each step, the model scores possible next tokens. The answer grows one token at a time.

Prompt: "The student opened GitHub and created a..."
repo
72%
branch
18%
pizza
3%

These numbers are illustrative. The key idea is ranking likely continuations, not looking up guaranteed truth.

Hour 1 question

Why does this thing work at all?

The simplest useful answer: an LLM has learned patterns in text and code, then uses the current context to predict useful next tokens.

text
->
tokens
->
probabilities
->
next token
Cold open: write "The best way to learn AI is..." and ask students to shout likely continuations.
Mental model

Start with autocomplete, then scale it up.

Phone autocomplete predicts a few likely next words. An LLM predicts the next token using a much larger context and a much richer model of patterns learned during training.

Small autocomplete

Looks at a short phrase and offers common continuations.

LLM

Looks at a long context and can continue explanations, code, plans, arguments, and conversations.

Stress the analogy's limit: an LLM is not just a phone keyboard. The useful part is next-token prediction as the interface to learned patterns.

Quick check

What is the model choosing during generation?

The useful mental model is repeated next-token generation. The final answer emerges from many local choices.
Tokens

The model does not read text the way you do.

Before text reaches the model, it is split into tokens: words, parts of words, spaces, punctuation, numbers, or code fragments.

"unbelievable" might become "un" + "believ" + "able"

This explains why spelling, letter counting, and exact formatting can feel strange. The model sees chunks, not your visual page.

Context window

Context is the model's working memory.

The model can only use what is inside the current context: your prompt, prior messages, pasted files, system instructions, tool outputs, and other text the app provides.

Inside context

Available for the next answer.

Outside context

Not directly visible unless retrieved, pasted, or remembered by the system.

Use a whiteboard box labeled "context." Put sticky notes inside and outside. Ask which notes the model can use.

Core limit

Probability is not the same as truth.

An LLM can produce a fluent answer because the text is likely, not because the claim has been verified. This is why we treat AI output as a draft, hypothesis, or plan until checked.

fluent != verified
Do not make this sound like "AI is useless." The point is role clarity: generation is powerful; verification is a separate step.
Quick check

Which statement is safest?

Good AI use means separating generation from verification.
Optional if time

Temperature: one control over variety

Some AI apps let developers adjust how predictable or varied the next-token choices are. Lower settings tend to be more conservative; higher settings can be more creative but less stable.

Low variety

Useful for summaries, extraction, and reproducible formats.

High variety

Useful for brainstorming, names, examples, and alternative phrasings.

Hour 2 question

Where does the behavior come from, and where does it break?

Training creates broad language and code ability. Post-training shapes the model into an assistant. Neither step adds a built-in truth detector.

Training data

The model learns from patterns in data.

Pretraining is prediction practice at massive scale.

The model sees large amounts of text and code and repeatedly practices predicting missing or next tokens. Over time, it learns patterns in language, facts, style, reasoning steps, and code.

It does not memorize a clean textbook of facts. It learns statistical structure from messy human data.

documents
->
tokens
->
training
->
base model
Two model roles

Base model is not the same as assistant.

A base model continues text. An assistant model follows user instructions.

ChatGPT-like products usually add post-training and interface rules so the model behaves more like a helpful assistant.

Base model

Continues text. It has broad learned patterns but is not yet tuned to behave like a helpful chat assistant.

Assistant

Post-training teaches the model to follow instructions, refuse some requests, and format answers more helpfully.

This distinction helps students understand why "the model" and "the product" are not identical.
Inference

Using the trained model is called inference.

At inference time, the system sends context into the model, receives next-token probabilities, chooses a token, adds it to the context, and repeats.

context -> model -> next token -> updated context -> repeat

This is why outputs can stream onto the screen one piece at a time.

Failure mode

Hallucination is fluent unsupported output.

A hallucination is an answer that sounds plausible but is unsupported, misleading, or false.

It happens because the model is generating likely text, not automatically checking truth against evidence.

A hallucination is not always nonsense. The dangerous version sounds plausible, fits the style, and still points you to the wrong answer.

Low-risk example

A made-up title in a brainstorming list.

High-risk example

A fake legal rule, source, medical claim, or financial fact.

Your job

Working rule

Use AI for drafts. Use evidence for decisions.

Verification means checking important claims against evidence outside the model's fluent answer.

The evidence can be a source, a calculation, a test result, a screenshot, a policy, or a person with authority.

AI output
->
claim list
->
source check
->
decision

For code, the evidence may be tests. For facts, it may be primary sources. For designs, it may be user feedback or constraints.

Quick check

Which output needs verification first?

Risk decides verification priority. Claims about policy, safety, money, health, or people need stronger checking.
Optional if time

Transformer intuition: words look at other words.

The transformer architecture lets tokens use information from other tokens in the context. You do not need the math today. The useful intuition is that meaning depends on relationships.

"bank" near "river" != "bank" near "loan"
Hour 3 question

How does an LLM become an agent?

An agent is not just a smarter answer. It is an LLM placed inside a loop with a goal, context, tools, and guardrails.

practical agent = LLM + goal + context + tools + loop + guardrails
Tool calls

Tools let the system act outside text.

A tool call is a request for an external action.

The model may ask to search, calculate, read a file, run code, or edit something. The surrounding app decides whether and how that request is executed.

A tool can search, calculate, run code, read a file, create a draft, send a request, or call another system. The LLM usually does not perform the action directly; it requests the tool.

Without tool

The model can describe what it would do.

With tool

The system can actually retrieve, compute, inspect, or change something.

Control loop

An agent loop repeats until done or blocked.

An agent is an LLM system that pursues a goal through a loop.

It plans, uses tools, observes results, revises, and stops when it is done, blocked, or waiting for human approval.

goal
->
plan
->
act
->
observe
->
revise

This loop is why agents need boundaries. A loop can be useful, but also expensive or risky if unchecked.

Challenge 5 - 18 minutes

Paper agent loop

Three roles: LLM, tool, and human approver. Solve one task using index cards. The LLM writes a proposed action, the tool returns an observation, and the human decides whether to approve risky steps.

LLM

Proposes next action and explains why.

Tool

Returns only what the action can observe.

Human

Approves, blocks, or asks for a safer plan.

Guardrails

Power should flow through approval.

Anything that spends money, publishes, deletes, emails, changes accounts, exposes private information, or affects another person should require stronger checks.

low-risk draft -> fast path
high-risk action -> human approval
Quick check

Which action needs approval?

Actions that affect other people or external systems should pass through human approval.
