Context checklist

Give the agent a brief, not just a wish.

A stronger agent request tells the model what to do, what it may inspect, what it must not touch, and what evidence would prove success.

Goal

What should be answered, built, fixed, or explained?

Sources

Which files, links, screenshots, notes, or examples should it use?

Constraints

What should stay unchanged, private, low-risk, or out of scope?

Tools

May it only read, or may it search, run, edit, or act?

State

What has already been tried, tested, broken, or approved?

Evidence

What output, source, diff, screenshot, or test would show it worked?

agent brief = goal + sources + constraints + tools + state + evidence
Pacing: 4 minutes. Keep this practical: students should use this as a prompt-prep checklist before coding, research, or review requests.

Control decision

How much control should the AI get?

Workflow design is a control choice. Decide which steps are fixed by the human, which choices the AI may make, and where approval is required.

Control-level check Task: Check whether a class source supports a claim. Fixed path | human sets sequence | approve claim label Choice path | AI chooses within approved sources | approve source choice Open path | AI proposes route | approve plan before tools Rule: more AI choice means more review.
Message: more AI choice increases the review burden. Students are selecting a safe control level for a school task, not building open-ended agents.
Workflow value

Why use a workflow?

A multi-step workflow is useful when it improves the work, separates independent steps, or makes parts easier to replace later.

Workflow benefit check Task: Check whether a class source supports a claim. Better through revision | plan, draft, check, revise Faster safe pieces | compare approved sources side by side Easier to upgrade | replace the checklist when the assignment changes Review question: Did the workflow fix evidence gaps, not just wording?
Frame this as practical workflow literacy. Do not use benchmark numbers here. For students, the key claim is that structured steps can improve quality, speed up safe independent checks, and make the process easier to inspect.
Task fit

Which agent tasks are easier?

Before building a workflow, judge the task. Clear steps, text inputs, limited tools, and reviewable outputs usually make the work easier to control.

Task-fit signals More controlled | clear steps, known text source, limited tools, visible evidence Middle ground | AI chooses among approved steps; human checks plan and evidence Harder to trust | open path, unknown sources, rich media, or real-world records
Keep this grounded in school-safe examples. The main skill is task decomposition: break work into smaller steps and decide which building block can handle each step.

Pattern map

Four patterns you will keep seeing.

Agentic workflows reuse the same building blocks in different shapes. Name the pattern, then decide what evidence a human should review.

Review loop | draft -> check -> revise with evidence Tool call | use an approved function or source when memory is not enough Plan first | choose steps before acting Role split | give separate jobs to researcher, checker, or editor Rule: more autonomy requires tighter limits, logs, and review.
Keep this as a bridge to later weeks. Role split becomes multi-agent work when each role has its own prompt, tools, and review responsibility. Do not copy external course diagrams, setup instructions, package lists, or named examples. Use school-safe task labels and connect back to visible evidence.
Planning

Planning lets the agent choose the route.

When the path is not fixed, ask for a plan from approved tools, then review it before the agent acts.

Fictional club records task Goal: Update an event signup summary. Approved tools: read_table, filter_rows, draft_message, create_review_ticket Possible AI plan: 1. Find rows for the selected event. 2. Count confirmed and waitlist students. 3. Draft a short summary for the teacher. 4. Create a review ticket before anything is sent. Human checkpoint: approve the plan, data source, and allowed tools first.
This is the student-safe version of the planning pattern. The key idea is not a retail example; it is that the agent proposes the sequence, while the class reviews the route and limits.
Multi-agent

Use multiple agents when the roles differ.

More agents are not automatically better. Split work only when the job has different skills, tools, or review standards.

Class event report Goal: Summarize a fictional signup table. Roles: data finder -> approved rows and counts checker -> verifies totals and missing evidence writer -> teacher-ready summary Why split? Different prompts, tools, and review checks. Checkpoint: human approves the report and disclosure.
Keep this as role decomposition, not agent hype. If one prompt can do the task clearly and safely, one agent is enough.
Team shape

Pick the communication pattern.

The team shape controls how easy the system is to understand, debug, and review.

Common team shapes Linear: finder -> checker -> writer Manager-led: coordinator assigns and reviews Hierarchy: specialists call smaller specialists All-to-all: flexible, hard to predict Student rule: start linear or manager-led. use hierarchy only with clear logs. avoid all-to-all for high-stakes work.
This simplifies the communication-pattern section into classroom design guidance. For this course, linear and manager-led are the practical defaults.
Planning quiz

Planning and multi-agent quick check.

Answer first, then open the card. Each answer should name the control point a human can inspect.

1. Planning vs. fixed workflow?

Planning lets the AI propose the steps for the specific request. A fixed workflow follows the same developer-chosen route every time.

2. Why code as a plan?

Code can combine many library functions for a data task, so the developer does not need to prebuild a separate tool for every possible question. Generated code still needs review and a sandbox.

3. Plan vs. tool access?

Tool access means the AI can request approved functions. Planning adds an ordered route: which steps to take, which tools to use, and what evidence should come back.

4. When split roles?

Use multiple agents when the work naturally has different jobs, such as finding evidence, checking it, and writing the final summary.

5. Easiest team shape?

Linear and manager-led patterns are usually easiest for students to trace. All-to-all communication is flexible, but harder to predict and review.

6. Main tradeoff?

Planning and multi-agent designs cover more varied tasks, but they reduce predictability. More flexibility needs clearer logs, limits, and human checkpoints.

Tool use

A tool call is a request, not magic.

The AI can ask for an approved function when memory is not enough. The app runs the function, returns the result, and a human checks whether the action was appropriate.

Tool request loop Student request -> AI decides: answer directly or request a tool? -> App runs the approved function -> Tool result returns to the conversation -> AI drafts an answer or next step -> Human reviews the tool, result, and action Rule: the AI requests; the system executes; the human remains responsible.
Emphasize the technical boundary: the model selects from available tool descriptions, but the surrounding software performs the actual call and records the result.
Plan format

Make the plan inspectable.

A plan is safer when students can read each step, expected output, and review check before execution.

Readable plan fields Step: what the agent intends to do Tool or source: which approved function, file, or class-safe source it will use Expected output: what evidence should appear after the step Review check: how a human will decide whether the step worked Class rule: structured plans are easier to parse, log, and challenge.
Mention that real systems may store plans in JSON or another structured format, but students should first learn the review shape: step, tool or source, expected output, and check.

Tool quiz

Tool-use quick check.

Open each card after answering. These are original LearnAI checks for tool choice, sandboxing, MCP, and tool descriptions.

1. What makes tool use different from a fixed function call?

With tool use, the AI chooses whether a relevant approved tool is needed. With a fixed call, the developer has already decided the sequence.

2. Why use a sandbox for AI-generated code?

A sandbox limits damage if generated code is wrong, unsafe, or too broad. It helps protect files, accounts, and private data.

3. What problem does MCP help reduce?

MCP standardizes how apps connect to tools and data sources, reducing repeated one-off connector work.

4. What must a tool description make clear?

It should explain the tool's purpose, required inputs, expected result, limits, and when a human approval step is required.

This is a formative discussion quiz, not a graded assessment. It adapts the concepts into original wording and avoids external answer choices.

Inside the loop

At the action boundary

39-54 min

Skills, MCP, and plugins extend the loop.

They are not the agent itself. They change how the agent works, what it can reach, or how capabilities are packaged. Today we recognize the mechanisms; we do not master building all of them.

Instructions

General rules, preferences, project conventions, and saved context.

Skills

Reusable task methods: checklists, rubrics, templates, scripts, and domain workflows.

MCP

A standard way for an agent client to discover and use external capabilities exposed by a server.

Plugins

Platform-specific packages for installing and sharing capabilities. Contents vary by ecosystem.

Review

Permissions, trust, logs, diffs, and human approval around expanded capability.

Mental model

Skill teaches method. MCP expands reach.

As an analogy: skills shape the agent's method; MCP expands what systems it can reach. In real tools, the boundaries can overlap, so classify by the main job.

Skill

Use when the agent needs a repeatable way to do a task: a writing rubric, audit checklist, slide style, grading method, or domain process.

MCP server

Use when the agent needs a live external capability: query a database, search a knowledge base, open a design file, create a ticket, or act through another service.

Connector standard

MCP reduces connector work, not review work.

A shared protocol can make tools and resources easier to connect, but it does not make every action safe by default.

MCP mental model Client: the AI app students can see Server: the connector that exposes data or actions Resource: data the client can read Tool: action the client can request Review: permissions, logs, limits, and approval Question before using any connector: What can it read, what can it change, and who approves?

Code execution

Code execution is powerful because it can change things.

Letting an AI write code can solve many small calculation and checking tasks, but arbitrary code must never run against real files or accounts without safeguards.

Classroom-safe code execution Good uses: safe calculation, CSV row check, chart validation, simple format check Required safeguards: sandboxed environment fictional or approved data read-only starter files backup or disposable workspace human review of output and errors Blocked: real inboxes, secrets, destructive file commands, private records
If demonstrating code execution, use a prebuilt sandbox or simulated output. Do not ask students to execute AI-generated code on personal devices without an explicit approved setup.
54-64 min

More capability means more ways to fail.

Context failure

The agent reads the wrong file, misses a rule, or uses stale conversation history.

Tool failure

A command fails, a search result is weak, or an external service returns misleading data.

Judgment failure

The agent over-edits, fabricates, hides uncertainty, or assumes approval it does not have.

capability without review is risk
Review habit

Human review is a component, not a courtesy.

Before action

  • Is the goal clear?
  • Is the context correct?
  • Are the tools appropriate?
  • Is permission needed?

After action

  • What changed?
  • Can I inspect the diff?
  • What evidence supports claims?
  • What still needs a human decision?
